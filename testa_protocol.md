# Testa — климатическая камера (UDP)

Реализация по образцу C++ `CTestaTCamera` / Java `TestaChamber`.
Исходники: `device/ethernet/testa/TestaCommands.java` (кодек),
`gui/devices/testa/` (клиент управления + эмулятор).

## Транспорт
- Протокол: **UDP** (дейтаграммы).
- Команда SetT шлётся на порт камеры **1300** (`host:1300`).
- Статус принимается на локальном порту **1200**.
- Схема обмена (важно для эмулятора):

```
контроллер (сокет, привязан к :1200)
   │── UDP →  camera:1300   (SetT, 32 байта)
   │←─ UDP ─  camera → контроллер:1200  (статус, 40 байт, периодически ≈1 Гц)
```
Камера сама периодически шлёт статус на порт 1200 клиента (отдельного запроса GetT нет —
статус приходит «пакетом»). Чтобы камера узнала адрес клиента, клиент сначала шлёт SetT
(из её адреса берётся IP, ответ уходит на `IP:1200`).

## Установка температуры (SetT) — 32 байта
| Смещение | Значение |
|---------:|----------|
| 0 | `0x02` |
| 1 | `0x33` |
| 2 | `0x88` |
| 3 | `0x66` |
| 4..11 | не заполняются |
| 12..15 | температура, 32-бит float IEEE-754, **little-endian** |
| 16..31 | не заполняются |

Float упаковывается как `Float.floatToRawIntBits`:
```
byte[12] =  bits & 0xFF
byte[13] = (bits >>> 8) & 0xFF
byte[14] = (bits >>> 16) & 0xFF
byte[15] = (bits >>> 24) & 0xFF
```
CRC нет. Ответ на SetT не читается.

## Статус камеры (GetT-данные) — 40 байт
Принимается датаграмма ровно **40 байт**, заголовок:
| Смещение | Значение |
|---------:|----------|
| 0 | `0x11` |
| 1 | `0x22` |
| 2 | `0x00` |
| 3 | `0x00` |

Данные:
| Смещение | Поле | Кодировка |
|---------:|------|-----------|
| 4..5 | `w` — текущая температура | знаковый short, little-endian, /100 |
| 6..7 | `w2` — уставка | знаковый short, little-endian, /100 |

```
short t  = (short) w;   °C = t  / 100.0   // текущая температура
short t2 = (short) w2;  °C = t2 / 100.0   // уставка
```

Датаграммы иного размера/заголовка игнорируются.

## Переустановка уставки (цикл испытания)
Уставку нужно посылать повторно, если:
- уставка ещё не задавалась (`dTSet == -1000`), либо
- заданная уставка (`dTSet`) не равна считанной из камеры (`dTSetRead`).

Т.е. контроллер отправляет SetT до тех пор, пока камера не подтвердит уставку в статусе.

## Сокеты / порты
- Контроллер: один `DatagramSocket`, привязан к `:1200`, шлёт и принимает на нём.
- Камера (эмулятор): слушает `:1300` (приём SetT), шлёт статус на `клиентIP:1200`.

## Реализация в проекте
- **Кодек** `TestaCommands`: `buildSetTemperatureFrame(float)` (32B),
  `isTemperatureDatagram(byte[])`, `parseActual`, `parseSetpoint`,
  `buildStatusDatagram(actual, setpoint)` (40B), `getStatusDatagramLength()`.
- **Эмулятор** (`gui/devices/testa/emulation`): `TestaServerService` (UDP :1300, рассылка
  статуса на :1200), `TestaEmulator` (ramp к уставке), панель/окно.
- **Управление** (`gui/devices/testa/control`): `TestaCommunicationService` (приём :1200,
  SetT на host:1300), `TestaControlPanel`.
- Меню: «Панели управления → Testa → Панель управления / Панель эмуляции».

Для проверки пары: запусти эмулятор (UDP :1300), затем панель управления
(host `127.0.0.1`, port 1300) — задай уставку, текущая температура должна подойти к ней,
а в логе виден UDP-обмен (SetT → статус).
